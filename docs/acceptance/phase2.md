## 2. 实测（服务端）

2026-11-08 00:52，`POST /api/v1/jobs/40a80bd6c17f/objects`（1123 帧，采样 225 帧，313 713 高斯，RTX 4060 Laptop，模型已缓存）：

| 阶段 | 耗时 |
|------|------|
| 检测 + 分割 + 渲染深度（225 帧，1220 个检测） | 205 s（0.9 s/帧） |
| 合并 → 169 个物体 | 6 s |
| 高斯归属（100 007 / 313 713 归到物体） | 2 s |
| 截图 + 关系（1974 条） | 6 s |
| **总计** | **301 s** |

首版产物偏"碎"：169 个物体里 87 个只在 2 帧出现、35 个一个高斯都没归到（无法高亮）；窗 26、门 12、灯 9 明显多于真实。
最多视角的物体（椅子 24 帧、窗 22、植物 16、箱子 12、沙发 11、电视 9）尺寸和位置都合理。

修正后（`MIN_VIEWS = 3`，丢掉没有高斯的物体）01:03 重跑：**285 s**，82 个合并物体 → 丢 6 个无高斯 → **76 个**，全部可高亮，
88 577 个高斯归到物体。每类：椅子 10、窗 10、箱子 9、植物 6、桌子 6、门 5、柜子 5、沙发 2、遥控器 2、键盘 2、冰箱 2、
笔记本电脑 2、窗帘 2，其余各 1。窗 / 门 / 椅子仍偏多（同一扇窗被拆成多个），真机上按第 1 节第 2 条对照实物判断。

真机对照（11-08）：准确率偏差，列表加上每个物体的「出现 N 帧」后看出 3–5 帧的基本都是误检，`MIN_VIEWS` 改为 **6**。

## 3. 已知限制

- 词表固定（`server/recon3d/objects/vocab.py`，v2 约 60 类），不在词表里的东西不会出现。
- 「改用高精重算」得到的新任务没有物体表，要重新点「识别物体」。
- 第一次识别会先从 Hugging Face 下载模型权重（见各 setup 文档的预下载步骤）。

## 4. v2 验收（结构 → 跟踪 → VLM 确认；设计见 `docs/superpowers/specs/2026-11-08-recon3d-objects-v2-design.md` §7）

在实验室 A6000 上跑。办公桌场景：把笔记本的 `server/data/jobs/40a80bd6c17f/` 整个目录拷到 A6000 的同一路径
（目录自包含，不用重新重建）；门窗场景：从最近拍的场景里选一个在 A6000 上重建。对每个场景：

1. 结构：地面、墙面数、门、窗与实物一致；点「门」高亮的是门板不是墙。
2. 表里**每一个**物体对照实物：标签对、高亮区域对。允许的失败：20 个里 ≤ 1 个标签错，0 个高亮溢出到墙地。
3. 白门必须是「门」或不出现，不得是柜子；手机必须是「手机」或不出现，不得是遥控器。
4. 同一物体不出现两次；两个相邻同类物体不合成一个。
5. 耗时 ≤ 10 分钟（A6000）；`log.txt` 里有 structure / track / verify / assign 四段耗时。
6. 第 1 节的 1、3、4、5、6、8 条（流程类）仍通过；列表分「结构 / 家具 / 物品」三节，每项显示「出现 N 帧 · 高 x.xx 米」。
