## 1. 为什么重做

v1 在办公桌场景（任务 `40a80bd6c17f`，1123 帧）的真机对照结论：

- **漏检多**：很多实物不在表里。
- **标签错**：白门 → 柜子、白花盆 → 其他类、手机 → 遥控器。共同点是**单帧 2D 外观相近**，而尺寸（门 2 m 高、落地）和位置（嵌在墙里）本可一票否决。
- **高亮区域错**：3D 归属不准，同一扇窗被拆成多个，背景高斯被吸进物体。
- 出现帧数 3–5 帧的几乎全是误检（`MIN_VIEWS` 已临时提到 6，治标）。

根因是路线：**逐帧 2D 检测 → 事后用 3D 点重叠拼身份**。身份靠反投影点集重叠判定，而渲染深度在边缘和漂浮物处不可靠、不同视角看到的只是物体的一部分，所以拼不起来；标签靠闭词表检测器在单帧上猜，不知道大小也不知道场景。

v2 把顺序反过来：**先定结构，再在连续帧上跟踪定身份，最后用尺寸、支撑关系和 VLM 多视角确认标签**。目标从"尽量多认"改为"**宁缺毋滥**"。

## 2. 目标 / 非目标 / 反目标

### 目标
- 表里出现的每个物体都**可信**：标签对、位置对、高亮区域是那个物体。验收标准见 §7。
- 房间大结构（地面、天花板、墙、门、窗）先识别出来，并成为后面所有判断的坐标系。
- 中等物体（家具、花盆、箱子）靠跨帧跟踪定身份，同一物体不再被拆成多个。
- 全管线在实验室 A6000（48 GB）上 1100 帧 **10 分钟内**。
- 手机端交互不变（按需点「识别物体」、列表、飞过去高亮）；列表按层级分节，每项显示尺寸和出现帧数。

### 非目标（这次不做）
- 认出所有物体。漏掉可以接受。
- 开放词汇。词表固定（用户定）。
- LLM 问答（后半段）；在 3D 里直接点选；用户编辑词表。
- 在高斯上学实例特征（Gaussian Grouping / LangSplat 一族）：它们解决的是任意视角像素级分割，需逐场景再训练，且身份仍来自 2D；我们要的是物体层的大颗粒语义，理解在物体层做，高斯只提供几何和最后的可视化。

### 反目标（出现即失败）
- 表里有明显错的标签（白门叫柜子）。
- 一个物体被拆成两个，或两个物体合成一个。
- 高亮溢出到墙地或只盖住物体一角。

## 4. 服务端算法

输入与 v1 相同：`capture.zip`（图像、ARCore 位姿、内参）、`scene.ply` / `scene.splat`、高精任务的 `poses_cv.npy`。深度仍由高斯渲染得到（v1 §4.4 的理由不变）。**不再采样 1/5 帧**：跟踪需要连续帧，全部关键帧按时间顺序参与。

进度阶段文案（手机 chip 上显示）：`识别物体 (结构)` 0→0.15、`识别物体 (跟踪)` 0.15→0.55、`识别物体 (确认)` 0.55→0.9、`识别物体 (归属)` 0.9→1.0。

### 4.1 结构层：房间坐标系与大结构

1. **重力与地面**。ARCore 世界系 Y 轴向上，位姿本身是重力对齐的，直接用。把所有帧的渲染深度反投成点云（每帧半分辨率，体素 3 cm 去重），在其中用 RANSAC 找**水平面**（法向与 Y 夹角 < 5°）：最低且面积 ≥ 2 m² 的是**地面**，最高且在所有相机位置之上的是**天花板**（没有就没有）。
2. **墙**。剩余点中 RANSAC 找**竖直平面**（法向与 Y 夹角 > 85°），面积 ≥ 1.5 m²，按面积从大到小取，两面墙法向夹角 < 10° 且距离 < 0.3 m 视为同一面。每面墙记平面方程和在平面内的矩形范围。
3. **门和窗**。候选来自检测器（见 4.2 的提议器）在该墙正视帧上的 door / window 框，但必须通过几何门槛才进入确认：
   - 候选的 3D 点 ≥ 80% 落在某面墙平面 ±15 cm 内（嵌在墙里）。
   - 门：底边距地面 < 15 cm，高 1.8–2.4 m，宽 0.6–1.2 m。
   - 窗：底边距地面 ≥ 0.3 m，高 0.4–2.2 m。
   不满足的候选**不会**降级成别的类别，直接丢弃（白门不许变成柜子）。
4. 结构元素也进物体表，层级 `structure`：地面、天花板、墙面 1…N、门、窗，手机上可以点、可以高亮。它们的高斯归属按"到平面距离 < 5 cm 且在范围内"算（§4.4）。

产物里多一块 `structure`：`floor_y`、`ceiling_y`（可空）、`walls: [{id, normal, d, extent}]`，供后半段问答用。

### 4.2 物体层：连续帧跟踪定身份

- **提议器**：Grounding DINO（沿用 v1 的 tiny 模型；A6000 上换 `IDEA-Research/grounding-dino-base`），每 10 帧跑一次，词表全量提示（分批），框阈值放宽到 0.25——它只负责"这里可能有个东西"，不负责最终标签。只有和当前所有在跟踪 mask 的 IoU < 0.5 的新框才成为新轨迹。
- **跟踪器**：SAM 2.1 **视频模式**（`facebook/sam2.1-hiera-small`，A6000 上 `hiera-large`），以提议框为提示，在后续帧上传播 mask；连续 15 帧 mask 为空则轨迹结束。每条轨迹就是一个候选物体的身份，**不再靠 3D 点重叠拼**。
- **轨迹 → 3D 片段**：每帧 mask 与渲染深度相交反投成点，累积到 2 cm 体素网格；只保留被该轨迹 ≥ 3 帧命中的体素（去掉边缘和深度噪声）。片段的包围盒取体素的 2–98 分位；尺寸 = 包围盒长宽高（在重力对齐坐标下，长宽取水平面上最小外接矩形）。
- **轨迹合并**（同一物体被遮挡后重新出现、绕一圈又回来）：两条轨迹**没有任何共同帧**，且体素重叠 ≥ 较小者的 50% → 同一物体。有共同帧的永远不合并（两只挨着的杯子就是两只）。
- 轨迹太短（< 5 帧）或体素太少（< 20 个）→ 丢弃。
- **支撑关系**（给确认层用）：片段底面距地面 < 10 cm → `floor`；底面距某个更大片段顶面 < 10 cm 且水平中心在其内 → `on:<该片段>`；≥ 60% 体素在某墙平面 ±15 cm 内 → `wall:<墙 id>`；天花板同理 → `ceiling`；否则 `none`。

### 4.3 确认层：按层级打标签，和上层"和谐"

- **词表**（`vocab.py` 重写，固定，约 60 类，**类别清单由开发者补全**：v1 的 40 类全部保留并归入层级，再补常见室内物体到约 60 类；用户只定"固定词表"这件事）：每类带中文名、所属层级、**尺寸范围**（高度 min/max、最长边 min/max，单位 m）、**允许的支撑**。层级三档：
  - `structure`：door、window（地面/天花板/墙由几何直接给出，不走词表）。
  - `furniture`：table、desk、chair、sofa、bed、cabinet、shelf、refrigerator、whiteboard、tv、curtain、mirror、printer、trash can、floor lamp 等。支撑只能是 `floor` 或 `wall`。
  - `item`：cup、bottle、book、remote control、phone、monitor、laptop、keyboard、mouse、plant（盆栽）、box、bag、backpack、lamp、speaker、headphones、clock、picture frame、pen、pillow、shoes、towel 等。支撑是 `floor`、`on:<家具>` 或 `wall`。
  例：door 高 1.8–2.4、支撑 floor+wall；chair 高 0.7–1.3、最长边 0.4–0.8、支撑 floor；phone 最长边 0.12–0.2、高 < 0.05（放着）或 < 0.2（立着）、支撑 on/floor；plant 高 0.1–2.0、支撑 floor/on。
- **处理顺序**：结构 → 家具（按体积从大到小）→ 物品（按体积从大到小）。
- **候选类别**：每个片段的候选 = 词表中**尺寸范围和支撑都通过**的类别，再用轨迹上提议器各帧的投票排序，取前 5。候选为空 → 丢弃。
- **VLM 确认**：Qwen2.5-VL（A6000：`Qwen/Qwen2.5-VL-7B-Instruct` bf16；laptop：`Qwen/Qwen2.5-VL-3B-Instruct` 4-bit）。输入：该轨迹 3–5 个最佳视角的裁剪图（mask 面积大、视角分散，框外扩 20%，拼成一张网格图）+ 文字：
  > 这是同一个室内物体的几张照片。它高约 H 米、最长边约 L 米，放在{地面/桌面上/贴墙}。它是下列哪一个：{候选中文名列表}？只回答其中一个名称；都不是或看不清就回答「不确定」。
  回答必须精确等于某个候选，否则丢弃。**同一物体问两次**（第二次打乱候选顺序），两次答案不同 → 丢弃。
- **和谐检查**（最后一道闸）：
  - 家具层两两 3D 包围盒 IoU > 0.3 → 保留体积大的，丢小的。
  - 物品层若与某家具包围盒 IoU > 0.5（其实是家具的一部分）→ 丢弃。
  - 任何物体的中心在所有墙围成的范围外 0.3 m 以上 → 丢弃。
  - 门、窗之外的任何类别若 ≥ 80% 体素在墙平面 ±15 cm 内且高 > 1.5 m → 丢弃（这正是白门变柜子的形状）。
- 每个物体的 `confidence`：提议器投票中与最终标签一致的帧占轨迹帧数的比例（0–1），VLM 两次一致才有这一步。`views` = 轨迹帧数（手机显示「出现 N 帧」）。

### 4.4 高斯归属

- 物品 / 家具：高斯中心落在该物体体素集（膨胀一格，即 ±2 cm）内 → 属于它。两个物体都命中 → 给体积小的（小物体在大物体上）。
- 结构：地面 / 天花板 → 到平面距离 < 5 cm 且 XZ 在其范围内；墙 → 到平面距离 < 5 cm 且在矩形范围内，且不属于任何门窗；门、窗 → 到墙平面距离 < 15 cm 且在其框范围内。
- 高斯一个都没归到的物体丢弃、重新编号（v1 的规则保留）。

### 4.5 产物（`objects.json` version 2）

每个物体在 v1 字段之上增加：`level`（structure / furniture / item）、`size: [l, w, h]`、`support`（`floor` / `ceiling` / `on:<id>` / `wall:<id>` / `none`）、`confidence`。顶层增加 `structure` 块（§4.1）。`objects.bin`、`thumbs/`、`relations` 不变。`frames_used` 改为参与的帧数（全部）。

### 4.6 代码与配置

- `server/recon3d/objects/`：新增 `structure.py`（平面拟合，纯 numpy，可单测）、`track.py`（提议器 + SAM 2 视频跟踪封装）、`segments.py`（轨迹→体素片段、合并、支撑，纯 numpy，可单测）、`verify.py`（词表约束 + VLM 问答 + 和谐检查；VLM 调用可注入假实现单测）、`vocab.py` 重写；`assign.py` 改为体素/平面归属；`merge.py` 删除；`pipeline.py` 重排阶段。`detect.py`、`render_depth.py`、`thumbs.py`、`relations.py`、`table.py` 沿用（`table.py` 加新字段）。

## 6. 性能预算（A6000，1100 帧 1920×1080）

| 阶段 | 预估 |
|---|---|
| 渲染深度（全部帧，半分辨率） | ~1 min |
| 结构平面拟合 | < 30 s |
| 提议器每 10 帧 + SAM 2 视频传播 | 2–3 min |
| VLM 确认（≤ 150 个候选 × 2 问 × ~1.5 s） | ≤ 7 min，通常 3–4 min |
| 归属 + 截图 | < 30 s |

总计目标 ≤ 10 分钟。laptop 档位不作承诺，用于验证链路。

## 7. 验收（`docs/acceptance/phase2.md` 新章节）

办公桌场景（把笔记本上的任务目录 `server/data/jobs/40a80bd6c17f/` 整个拷到 A6000 的同一路径——目录自包含：`capture.zip`、`scene.ply`、`scene.splat`、`status.json`，识别不需要重新重建）+ 一个有门窗的房间场景（用户最近拍的场景里都有门窗，从中选一个在 A6000 上重建）。对每个场景：

1. 结构：地面、墙面数、门、窗与实物一致；点「门」高亮的是门板不是墙。
2. 表里**每一个**物体对照实物：标签对、高亮区域对。允许的失败：20 个里 ≤ 1 个标签错，0 个高亮溢出到墙地。
3. 白门必须是「门」或不出现，不得是柜子；手机必须是「手机」或不出现，不得是遥控器。
4. 同一物体不出现两次；两个相邻同类物体不合成一个。
5. 耗时 ≤ 10 分钟（A6000）。
6. v1 的 1、3、4、5、6、8 条（流程类）仍通过。

## 8. 留给实现者的决定

- RANSAC 参数（内点阈值、迭代次数）、体素网格实现（dict / 稀疏数组）。
- 最佳视角的具体打分与网格拼图布局；VLM 提示词的精确措辞（保持 §4.3 的信息项）。
- SAM 2 视频模式在 transformers 里的接口细节（`Sam2VideoModel` / 独立 `sam2` 包二选一，以能跑为准）。
- 墙的矩形范围怎么从内点算；天花板缺失时的处理。
- 各类尺寸范围的具体数值（§4.3 的例子是起点，实现者按常识填满词表）。
- 测试：`structure.py`、`segments.py`、`verify.py`（假 VLM）纯 CPU 单测；跟踪和 VLM 用 `@pytest.mark.gpu` 对真实拍摄包前 60 帧跑。

## 9. 开发者做的决定（用户可推翻）

1. 结构元素（地面、墙、天花板）进物体表、可高亮——用户只要求"先识别"，进表是顺带的。
2. 提议器仍用 Grounding DINO，但只做"这里有东西"的提议，不做最终标签。
3. VLM 选 Qwen2.5-VL-7B（A6000）/ 3B 4-bit（laptop）；同一物体问两次取一致。
4. 轨迹合并"无共同帧 + 体素重叠 ≥ 50%"；短于 5 帧的轨迹丢弃。
5. 高斯归属从 mask 投票改为体素命中。
6. 词表约 60 类、三层级、带尺寸与支撑约束；不满足约束的候选直接丢弃而不是降级到别的类。
7. 全部关键帧参与（不再 1/5 采样）。
8. 验收用的办公桌任务目录从笔记本拷到 A6000，不重新重建（保持和 v1 可比）。
