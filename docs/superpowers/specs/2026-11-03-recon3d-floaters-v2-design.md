# Floater 治理第二轮：方案

日期：2026-11-03。输入：`suggestions for floater removal.md`（根目录）＋ 第一轮实测（`docs/acceptance/phase1.md` §5）。

## 1. 我们的场景对号入座

拍摄条件：手机绕房间慢走，190–340 个关键帧，视角稠密；没有行人/宠物等瞬态物体；室内；手机自动曝光、自动白平衡全开。建议文档列的四个 floater 来源里：

| 来源 | 适用？ | 我们已有的证据 |
|---|---|---|
| 外观不一致（曝光 / 白平衡） | **是** | 手机 AE/AWB 开着；同一面墙在不同帧亮度不同，模型只能用半透明点"补光" |
| 弱纹理几何欠约束（白墙、地板、玻璃） | **是** | 第二包最差帧 #63–67（PSNR 11–13 dB）正是玻璃隔断 + 细叶植物 |
| 近相机 floater（只对一两个视角有贡献） | **是** | 手持贴近家具拍；floater 分数算的就是"离最近深度点 > 阈值"的高斯 |
| 天空 | 否 | 室内。但**窗户和镜面**行为类似天空：无视差，模型往远处堆点。刚加的场景范围裁剪（fa5cc87）正好砍这一类 |

第一轮结论必须带进来：
- **深度损失（绝对 L1 对传感器深度）无效**：三个包上 floater 分数变化 < 0.002，多花 40% 时间。原因：ToF 深度本身 5–20 cm 噪声，硬约束等于把噪声学进去。
- **光度位姿优化有害**：PSNR −2.2 dB。ARCore 位姿相邻帧一致性 0.6 px / 0.7°，不是主因。
- **真正有效的是"少放错点"**：置信度过滤初始点云让 floater 分数降 35%。这提示：**剪枝类方法收益最大**，因为我们的问题是错点太多，不是好点太少。
- 当前训练配置：`DefaultStrategy`（15k 步，稠密化到 7.5k，每 3000 步 opacity 重置），L1+SSIM，黑背景，无正则；导出只丢 α < 0.005，等于什么都不丢。

## 2. 推荐顺序

按"预期收益 ÷ 实现成本"排。每一步独立可测、可开关（`Profile` 字段），先在三个已有拍摄包上用 `eval_scene.py --train` 对照，再改默认。

### 第 1 步：贡献度 + 多视角可见性剪枝（建议文档 §2）＋ 收尾 SOR（§5）

**为什么第一**：直接针对"错点太多"；我们视角稠密，真实几何被几十个相机看到，floater 只被一两个看到，这个判据在我们的数据上区分度最高。不引入新依赖，不改 CUDA。

**做法**
- `recon/contrib.py`：`compute_contrib(params, viewmats, Ks, W, H, downscale=2) -> (total[N], nviews[N])`。把颜色换成全 1 的 `[N,1]` 特征，`rasterization(..., sh_degree=None)`，对特征求梯度得到每个高斯在该视角的像素权重和。300 帧 × 480×270 在 4060 上约 10–20 s。
- 在训练里跑三次：稠密化结束时（`iters/2`）、`3·iters/4`、训练结束。剪掉 `nviews < 3 或 total < 0.5 px`，用 `gsplat.strategy.ops.remove`，日志记数量。
- 训练结束再做一次 3D 离群点滤波（SOR）：高斯中心 kNN（k=8）平均距离 > 均值 + 3σ 的删掉。`_knn_mean_sq_dist` 已有 cKDTree，加十行。
- `Profile` 新字段：`contrib_min_views: int = 3`、`contrib_min_px: float = 0.5`、`sor_sigma: float = 3.0`（0 关闭）。

**风险**：房间边缘只被少数帧扫到的区域可能被误删。对策：先导出被剪的点为单独 PLY 看一眼位置（`eval_scene.py --dump-pruned`），再定 `min_views`。

**预期**：floater 分数再降 20–40%，PSNR 持平或微升（floater 本来就在拉低 test 视角）。半天到一天。

### 第 2 步：opacity / scale 正则 → 再试 MCMC（§1）

**先做便宜的一半**：在现有 `DefaultStrategy` 上加 `opacity_reg = 0.01 · mean(σ(opacity))`、`scale_reg = 0.01 · mean(exp(scale))`。两行损失，让模型不再靠大量半透明大点"糊"过去。这本身就常常让 floater 明显减少。

**再试 MCMC**：gsplat 1.5.3 自带 `MCMCStrategy(cap_max, noise_lr, refine_start/stop, min_opacity)`。要改的地方：去掉我们自己的 `_enforce_cap` 和 opacity 重置（MCMC 不重置，而是把低 α 点"搬"到高 α 点附近）；`cap_max = profile.max_gaussians`；位置噪声需要 `means` 的学习率给它。第 1 步的剪枝在 MCMC 下改成"把 α 压到 1e-4 让 relocate 回收"。

**判据**：floater 分数、PSNR、时间三项对照，MCMC 不赢就不换（DefaultStrategy 我们已经调顺了）。半天。

### 第 3 步：外观补偿（§1 的双边网格，先做简化版）

**问题**：AE/AWB 导致同一表面不同帧颜色不同，是室内 floater 的一大来源，我们完全没处理。

**先做简化版——逐帧仿射颜色校正**：每帧学一个 3×4 矩阵（初始化为单位），渲染结果 `rgb' = A·rgb + b` 后再算损失；导出时丢掉。参数量 300×12，几乎零成本，不要新依赖。90% 的曝光/白平衡差异是全局的，仿射够用。
**不够再上双边网格**：`fused-bilagrid` 需要在 WSL 里编 CUDA 扩展，先验证能装再说。

**另一个方向，拍摄端**：ARCore 的 `CameraConfig` 不能直接锁曝光，但可以考虑在录制开始时记录一次 AE/AWB 并通过 shared camera 锁定（需要验证 Pixel 10 Pro 上行为）。放第二轮之后。

**预期**：墙面、天花板附近的"补光"团块减少；PSNR 升 0.3–1 dB（同一表面不再被迫拟合多种亮度）。一天。

### 第 4 步（实验性）：用**自己的传感器深度**做尺度无关的局部 Pearson 约束（§3 的变体）

建议文档用单目深度模型 + Pearson。我们**已经有**深度，不必跑 Depth Anything（4060 上还要和训练抢显存）。第一轮失败的是"绝对 L1"，而 Pearson 按 64×64 patch 算、只约束局部相对结构，正好绕开 ToF 的绝对误差和尺度漂移，专治白墙/地板的凹凸。

- 复用 `depth_loss` 的渲染路径（`RGB+ED` 和 `depth_pose` 单独渲染都现成），把损失换成 patch Pearson，权重 0.1 → 0.01 线性衰减。
- 仍然只对 `conf ≥ 0.5` 的像素算。

这一步只有在第 1–3 步之后墙面仍然"鼓包"才值得做。一天，结果不确定，所以放最后。

### 不做
- 天空 mask / 天空模型：室内无天空。窗户靴窄，场景范围裁剪 + 第 1 步剪枝覆盖。
- `random_bkgd`：房间封闭，背景几乎看不到，收益小且可能和窗户区域冲突。
- 2DGS + 法线先验：PSNR 会掉，而且查看器是 .splat，不需要 mesh。
- 稀疏视角方法、瞬态 mask：不符合条件。

## 3. 评估方法（每一步都用同一套）

- `scripts/eval_scene.py <job> --train --tag <名字> [覆盖参数]`：test 视角 PSNR 中位数、floater 分数、高斯数量、训练时间，写 `eval.json`。
- **新增**：`--orbit-video`：沿训练轨迹**抬高 0.5 m** 渲染 30 帧拼成图/视频（建议文档的"偏离轨迹"检验）——floater 在训练视角里会被遮住，偏离后才暴露。这是比 PSNR 更贴近"手机上看着干净"的指标。
- 对照包：`cfd1968452b2`（office，193 帧，平滑深度）、`2fe7b607c543`（340 帧，平滑深度）、`5cba40b51c1e`（282 帧，Raw Depth + 置信度）、`9f6d49647dfe`（最新一包，先跑一次默认拿基线；它是旧代码训的，没有场景范围裁剪）。
- 每步的默认值只在三个包上都不变差（PSNR −0.2 dB 以内、floater 分数下降）时才改。
